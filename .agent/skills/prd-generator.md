SKILL NAME
prd-generator

CATEGORY
product

PURPOSE
Convertir una idea o solicitud en un Product Requirements Document (PRD) claro, completo y listo para guiar el desarrollo de software.

WHEN TO USE
Usar esta skill cuando se recibe una idea de producto, una funcionalidad o un concepto que debe transformarse en una especificación de producto estructurada.

INPUTS
- idea del producto
- problema a resolver
- contexto del negocio (si existe)

INSTRUCTIONS
1. Analiza la idea o solicitud inicial.
2. Identifica el problema principal que el producto debe resolver.
3. Define el objetivo del producto.
4. Identifica los tipos de usuarios.
5. Define casos de uso principales.
6. Define funcionalidades clave.
7. Define requisitos funcionales.
8. Define requisitos no funcionales.
9. Identifica riesgos o incertidumbres.
10. Define criterios de éxito del producto.

BEST PRACTICES
- Priorizar claridad sobre complejidad.
- Evitar ambigüedad en los requisitos.
- Mantener el documento orientado a producto y negocio.
- No incluir detalles de implementación técnica profunda.

CONSTRAINTS
- No generar código.
- No diseñar arquitectura técnica completa.
- No asumir información no proporcionada.

OUTPUT FORMAT (Markdown)
# Product Requirements Document
## Product Summary
## Problem Statement
## Product Goals
## Target Users
## Core Use Cases
## Feature Overview
## Functional Requirements
## Non Functional Requirements
## Risks and Unknowns
## Success Metrics

QUALITY CHECK
- El documento debe permitir a un arquitecto técnico diseñar el sistema.
- Debe ser comprensible sin contexto adicional.
